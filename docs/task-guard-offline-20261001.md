# 任务离线拦截：固定类型、原话证据与客服核实提醒

2026-10-01。新增独立 `copilot/task_guard_prototype.py`、`scripts/check_saved_task_guard.py`。本轮API调用0，没有修改桌面或生产回复入口。

## 输入与拦截

候选只接受tasks/questions两组，单项仅有type与evidence，不接受text、reason等模型自由正文。类型来自固定表：核实商品、不适、换货、退款、报销、回访。程序根据类型生成任务展示，不拼接模型句子、金额或历史期限。证据保留原话及引用，明确与任务文字分开。

每个任务必须位于调用方源文核对后的scope，并覆盖scope所要求的消息引用。无法确认scope则阻断；P0不适任务缺失也阻断。scope与provided是调用方可信输入边界，不是模型输出；source_reviewed只是来源声明，没有身份认证，更不能靠模型自己填写来获得权限。引文存在也不等于语义支持，结果始终需要人工核对。

已提供信息由provided及引用记录。已知图片、订单、资料、账户、用药信息不允许作为补问类型再次提出；任何questions通过后也只转成“客服先核实”的内部提醒，不直接询问客户。P0发生时间/当前变化尚未被确认已有记录时，程序补上两条客服检查提醒；没有记录不等于客户未说过。此提醒不是诊断或治疗建议。

## 本轮前后对照

| 原错误/风险 | 拦截结果 | 新结构可显示的内容 |
| --- | --- | --- |
| 报销任务夹带“需提交票据原件” | 自由text字段或旧版结构被拒绝，不采纳、不覆盖草稿 | 核对此前费用报销安排及已有票据记录；材料要求另行核实。 |
| 当前任务写“专员24小时内电话回访” | 模型正文不进入任务展示；24小时只能保留在历史证据里 | 核对此前回访安排及实际进度；历史时限不作新的保证。 |
| 已发图片但再次要求补图 | 已提供类型命中时阻断整个候选 | 原稿保留，提示先内部核对已有记录 |
| 初次商品问题泛化出退款/发货全部动作 | 超出已核对任务scope，阻断候选 | 当前只显示核实商品问题及适用处理方式 |
| 不适场景漏掉时间/当前变化 | 程序补充内部核实提醒；P0任务本身缺失则阻断 | 请客服先确认是否已有记录，确认缺失且必要后再询问 |

## 实际验证

7项本地测试通过：历史期限只留证据、自由文字原件要求拒绝、已发图补问阻断、关键不适信息提醒、无关任务/缺少方案依据拒绝、P0遗漏/错误引文拒绝、未审核scope拒绝和输入不变。

读取已保存v2的4份真实输出：全部因旧自由文字结构而阻断。这是整个旧协议不再受支持，不代表程序逐句理解并找出了所有语义错误。另对4份**明确人工编写的类型化替代样例**生成待审核预览，验证正常任务仍可展示。没有自动将错误模型文本改成正确类型，没有真人逐条批准，也没有新模型生成。

结果在 `.scratch/task-guard-offline-20261001/results.json`，含旧任务、拒绝原因、人工替代来源、审核scope和新预览。输入目录全部JSON哈希回放前后相同。历史API输出保留不动，原稿在成功及失败路径都保留。

## 尚未解决

目前防止了模型自由正文直接变成任务，仍需独立验证模型如何选择任务类型以及scope的来源。不得把人工scope套入实际使用后声称全自动理解；未提供可靠scope时继续阻断。新模型类型提取、真实业务凭证适配及桌面集成均未实施，本轮不额外调用API。
