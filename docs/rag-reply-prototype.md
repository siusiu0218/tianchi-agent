## 运行

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/rag_reply_prototype.py
```

程序执行本地检查，打印通过数、示例预览和保留的原稿。加 `--json` 可查看逐项检查结果。所有模型响应来自本地函数，没有 API 请求、真实业务操作或自动保存回复。

## 本轮实际实现

`copilot/rag_reply_prototype.py` 提供三个独立接口：

- `prepare` 核对当前会话、回放时点与消息引用，运行原有风险规则及检索筛选，生成本次上下文和快照标识。
- `validate_selection` 检查响应仅含 `context_id` 和 `segment_ids`，拒绝未知片段、额外正文或执行字段，并要求保留必答项。
- `propose` 调用注入的本地模型函数，重新读取当前快照，核对通过后仅返回预览。异常、来源变化、会话变化或草稿变化时不提供旧建议。

准备上下文时，当前消息获得可回查的临时引用。检索结果仅投影资料 ID、类型、版本、允许用途和整理后的参考要点。历史案例原文、旧承诺示例、原稿及订单账号字段不进入选择上下文。当前消息仍按待分析材料处理，不能作为系统指令。

实际输出不是模型自由撰写的文字。模型只能选择程序提供的片段，正文由程序按固定顺序拼接，原稿始终单独保留。现阶段全部必要片段都要求出现，因此这是验证协议与状态恢复的保守基线，不证明模型或检索改善了表达质量。

## 通过检查的行为

| 情况 | 本轮结果 |
| --- | --- |
| 模型夹带“已退款99元”“保证48小时发货”等正文 | 额外正文不符合协议，拒绝结果；中文金额及时限同样不能绕过 |
| 用未知片段或字符串列表伪装业务完成事实 | 拒绝，不拼接这些文字 |
| 模型增加退款动作、覆盖风险字段 | 拒绝额外字段；没有执行业务动作的接口 |
| 模型遗漏阶段核实、已有图片说明或 P0 跟进 | 拒绝遗漏，不提供不完整预览 |
| 当前消息或参考要点含忽略规则等指令 | 固定片段白名单仍由程序控制；模型无法修改校验副本 |
| 生成期间客服修改草稿 | 返回过期状态，保留最新草稿 |
| 切换会话、变更来源版本、修改来源原文或撤销审核 | 快照变化，拒绝旧建议；即使版本标签没变也会检查内容 |
| 生成期间新增 P0 线索 | 拒绝旧建议并返回当前快照的新风险级别 |
| 模型异常或无法再次读取当前快照 | 不生成替代成功结果；返回明确失败及原稿供上层保留 |
| 正式知识无命中 | 可预览资料不足及待核实提示，不补写政策 |
| 图片消息已存在但没有查看图片 | 仅说明消息存在并核对附件可用性，不声称已识别或确认破损 |

快照标识包含当前会话、查询、资料内容与版本、草稿和上下文。调用方必须在完成时重新执行 `prepare`，不能把旧快照当作当前状态传回。未来接桌面时还需在实际应用预览或替换的瞬间再检查状态；本轮没有验证多线程 UI 的完整流程。

## 引用的含义

预览附带每个片段的类别和当前消息定位信息。`current_record` 用于已有图片消息等可直接核实的记录；`service_language`、`verification_plan` 和 `risk_followup` 是服务表达或核实建议，引用说明为何需要回应，不证明退款、换货或发货已经完成。资料缺口片段明确标为 `retrieval_gap`。

本轮不从历史案例生成本客户的金额、时限或执行状态，也没有把检索要点直接拼接为回复正文。这解决的是这条受约束路径的输出边界，不代表任意自由生成回复都能被可靠核验。

## 后续边界

当前阶段与前提由调用方给定，没有自动识别新处理阶段；候选案例仍待审核，正式商品资料、政策和独立样本仍缺失。原型上下文也不是用于外传的匿名化数据，连接真实模型前需要沿用项目的数据预览、脱敏与授权流程。

下一步若要评估实际 RAG 效果，应先明确允许生成哪些有证据的内容以及逐项验收标准，再扩展到自由文字生成。本轮固定片段路径可保留为失败降级参考，但不能以它的通过率声称 RAG 提升了回复质量。桌面接入及真实模型调用尚未实施。
