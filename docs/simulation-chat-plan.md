# 微信式 AI 客服测试窗口：实现安排

日期：2026-10-07。状态：已实现并完成源码界面及自动回归验收；真实模型语义质量未在本轮验证。

用户补充决策：第一版只做空白对话；AI 回复期间允许输入，回复完成后才能发送下一条。2026-10-07 用户确认“开始”后执行本安排。

## 目标与已确认设计

用户固定扮演客户，连续发送消息，AI 扮演客服直接回复到本地测试聊天；用户可主动让 AI 总结当前会话。布局采用微信式会话列表与气泡，颜色保持共情副驾现有主题。

- 左侧：历史测试列表、新建对话；切换与重启后恢复已保存的记录。
- 中间：顶部显示对话名称和测试状态，AI 客服在左、客户在右；底部只有客户输入框和发送按钮。
- 右侧：生成摘要／更新摘要，展示客户当前诉求、前期沟通情况、建议处理方式、待确认内容；可查看原话依据。
- 颜色：主色 #5968D9，客户气泡浅蓝紫，AI 气泡白色，背景暖灰白；风险警示保留独立提示色。
- 入口：顶部的“模拟对话测试”移入左下角“设置”菜单。菜单首项是模拟对话测试，第二项是现有模型连接设置。
- 现有“打开数据文件”也归入该菜单，按既定默认方案实现。

## 当前实现依据

desktop/simulation.py 的 SimulationWindow 继承 MainWindow，在正式工作台上方增加客户输入框，下方仍采用 AI 建议、草稿核对、模拟发送流程。测试入口位于 desktop/window.py 顶部菜单；左下角设置目前直接打开模型连接窗口。

copilot/simulation.py 已提供独立测试消息数据源，测试库为 EmpathyCopilot/simulation/tests.sqlite3。desktop/handover.py 已有主动模型摘要、来源校验和失败显示；desktop/widgets.py 的 ChatFeed 已提供聊天气泡。应复用这些能力，避免另建一套风险、模型或摘要规则。

实现采用独立 QMainWindow 组织测试界面，复用 ChatFeed、回复生成及 HandoverPane，模型设置对话框提取到 desktop/model_settings.py。旧版通过继承工作台附加客户输入框的结构已替换。自动回复写 test_ai_messages，继续读取原有本地人工模拟回复，不伪造人工审核记录。

## 交互与状态约定

1. 新建对话为空，摘要显示待生成，不自动产生摘要或虚构背景资料。
2. 客户发送后先保存消息，再发起一次回复请求；聊天中显示“正在回复”。发送动作本身代表在此测试中请求 AI 回复。
3. 合法回复保存为本地客服消息并显示在左侧。正式客服窗口仍保留现有核对、确认和模拟发送规则。
4. 缺少模型配置时提示进入模型连接设置；请求失败或回复被校验拒绝时显示原因和重试入口，不把模板或失败草稿当作成功回复。
5. 生成期间可以编辑下一条消息，但本会话暂不重复发送；防止双击和重试造成重复客户消息或重复客服回复。
6. 切换或新建对话后，迟到结果不得写入另一会话；按会话 ID、消息版本和请求身份校验，过期结果丢弃并允许返回原会话重试。关闭窗口时妥善结束或等待任务，不能留下仍运行的 QThread。
7. 摘要由用户点击生成／更新，走真实模型摘要链路。新增任一聊天消息后标记旧摘要待更新，旧内容保留供查看，不能显示成已反映最新聊天。
8. 回复必须使用当前完整多轮上下文。没有摘要或摘要过期时，不能阻断客户聊天，也不能把旧摘要当作最新事实；复用现有来源核查与遮蔽逻辑。摘要与回复请求第一版串行执行，避免重复调用及结果交叉。
9. 生成摘要时冻结来源版本，来源变化后拒收旧结果。摘要失败保留已有有效内容、显示失败原因，允许重试；人工纠正和引用依据继续可追溯。
10. P0 风险即时显示，不等待模型或摘要。空白测试没有订单、工单和图片；测试操作仅写独立本地记录。

## 验收清单

- 左下角设置菜单打开测试、模型配置和数据文件入口；顶部不再重复显示测试入口。
- 新建、历史切换、重启恢复正常；未发送文本在切换时保留，记录不会串会话。
- 客户位于右侧，AI 位于左侧；聊天可连续阅读，自动滚动不强行打断用户查看历史。
- 第一条消息及连续多轮均能触发 AI；客户改口“换货改退款”后回复和摘要反映最新诉求，不重复保存客服消息。
- 网络失败、非法输出、缺配置、保存失败、重试、切换和关闭均有明确行为，不丢客户已输入文本。
- 不适消息立即触发可追溯 P0；回复遵循已有医学与越权承诺边界。
- 摘要首次待生成，点击才调用模型；新消息后待更新；更新失败保留旧内容并明确状态；引用定位正确。
- 正式客服的草稿保护、人工确认、摘要生成和风险逻辑无回归；原始工作簿只读，测试记录与正式审核记录隔离。

自动验证先运行直接相关测试：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_simulation tests.test_desktop tests.test_handover -v
```

共享回复、摘要或编排适配完成后运行全量测试与固定评测，并逐项检查黄金案例、风险证据、P0 和草稿边界断言：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/evaluate.py
```

可见验收必须关闭旧验收实例、从更新源码启动，使用独立测试状态验证主窗口菜单和完整测试窗口；复核 S00001 商品破损换货与 S00268 不适 P0，同时建立空白测试检查连续聊天、改口、摘要更新和重启。调整 scripts/check_desktop_simulation.py 适配新流程，保存截图和结果。

自动测试用假模型，证明状态与调用链路；真实模型的回复及摘要内容需单独人工检查并记录实际调用次数、来源和失败项。真实接口未配置或未运行时应明确标记未验证，不能以假模型通过宣称真实语义质量通过。
