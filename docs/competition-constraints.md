## 二、本地数据边界

本地 Excel 是 **AI 生成的虚构 MOCK 数据**，只适合验证产品流程、关联逻辑和模型评测方法，不能证明真实投诉率、真实客服效率或真实商业收益。

| 检查项 | 只读核查结果 | 可做与不可做 |
| --- | ---: | --- |
| 聊天 | 138 个会话、998 条消息 | 可做会话级理解；切分评测集时不得按消息随机拆分 |
| 订单 | 113 笔，113/113 能关联聊天 | 可还原订单事实；编号必须按字符串读取 |
| 工单 | 80 张，80/80 能关联聊天和来源订单 | 可还原服务轨迹和闭环状态 |
| 场景标签 | 一级 10 类、二级 41 类 | 仅用于离线评测，不能作为模型输入 |
| 情绪/风险标签 | 没有现成列 | 必须自建标注规范或弱标签规则，不能宣称是官方金标签 |
| 图片 | 29 条 `image_path`，本地实际文件 0 个 | 只能演示图片接口和缺失降级；不能宣称已完成真实多模态验证 |
| 不良反应 | 10 张工单；症状、停用、就医、批次字段均有值 | 只能视为消费者自述和 MOCK 登记，不是医学诊断或病历 |
| 公式 | 0 个公式单元格 | 工作簿是静态样例数据，不是计算模型 |

## 五、项目执行门槛

- 使用外部 API、联网或第三方托管时，只发送完成任务所需的最少字段，并记录服务商、模型版本、发送字段、成本、数据流向与失败降级；密钥不得进入仓库。
- 项目“未禁止即允许”的推进决策不是官方许可；如后续官方规则收紧，立即按官方要求切换或停止相关能力。
- 每个 Demo 事实都能回指原消息、订单或工单字段；没有数据时明确显示“暂未查询到”。
- 所有退款、补偿、工单创建和高风险处置必须经人工确认。
- PPT、视频和代码统一说明：数据为 MOCK、图片缺失、不良反应不是诊断、效果不可外推。
- 提交前 72 小时重新核查官网和答疑群，保存规则截图或公告原文。
