# 本地 RAG 检索原型

2026 年 10 月 1 日。本轮完成独立检索原型、合成边界检查和一个待审核案例结构。原型回答的问题是：能否在关键词排序前，排除来源类型、适用范围、处理阶段、版本、时间或审核状态不符合的资料？

目前通过本地检查，尚未接入模型回复或桌面程序。内置演示资料全部是合成夹具，不能当作商品知识或售后政策。关键词命中数不是事实正确率。

后续已完成独立的回复上下文与本地假模型验证，见 [RAG 回复上下文与假模型验证](rag-reply-prototype.md)。其输出采用固定片段选择，仍未接入真实模型或桌面。

## 运行

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/rag_prototype.py
```

终端用 `n` 查看下一例、`p` 查看上一例、`e` 查看完整来源和状态、`q` 退出，输入后按 Enter。示例和状态只保存在内存中。

```powershell
# 检查全部合成边界并打印结果
.\.venv\Scripts\python.exe scripts/rag_prototype.py --check

# 输出完整的演示状态 JSON
.\.venv\Scripts\python.exe scripts/rag_prototype.py --json
```

没有新增依赖、配置项或模型请求。代码分别位于 `copilot/rag_prototype.py`（独立纯函数）和 `scripts/rag_prototype.py`（终端演示及边界检查）。现有应用没有导入这个模块。

## 筛选与返回

先核查元数据，再筛选正式或合成模式、审核状态、来源类型、店铺与场景、处理阶段和必要前提。随后检查来源及审核时间、同会话或模板组、商品版本与有效期，最后按命中的人工整理关键词数量排序。并列按资料 ID 排序，默认最多返回 3 条。

| 情况 | 行为 |
| --- | --- |
| 没有正式政策，只有历史案例 | 返回无命中，不能拿案例填充政策结果 |
| 尚未审核 | 排除；真实来源需 `approved`，合成演示需 `fixture_approved` |
| 资料旧，但审核发生在回放点之后 | 排除；来源时间与审核时间均不得晚于回放点 |
| 来源消息晚于文档声明的可用时间 | 判定元数据无效 |
| 客户刚报告问题，案例处于接受方案阶段 | 排除；即使阶段相同，缺必要前提也排除 |
| 商品版本未知或错误 | 不自动猜测版本，排除资料 |
| 政策到期、尚未生效或有效期缺失 | 排除；使用起点包含、终点不包含的有效期 |
| 同一会话或同一模板组 | 排除，避免检索自身或重复模板 |
| 同一知识条目的多个有效版本同时命中 | 返回冲突状态，等待人工核实，不以关键词数决定权威版本 |
| 原文含旧金额、时限或指令 | 保留在人工核对原文区；原型仅返回另行整理的参考要点，不执行原文 |
| 当前会话有不适线索 | 现有确定性风险规则独立计算，检索结果不参与降低风险 |

命中结果保留资料 ID、类型、文档版本、适用范围、审核状态、来源及审核时间、来源原文与引用 ID。案例的 `allowed_use` 为 `structure_only`，并列出不得迁移的事实类别。所有结果均为 `reference_only`，没有发送、退款、建单等动作。

`reference_points` 是人工审核后可借鉴的要点；`evidence_for_review_only` 是原文核对区。两者分开是接口约束，不是自动删除不安全内容的算法。未来若把完整结果直接送入模型，仍可能发生旧事实污染或提示注入，必须单独设计生成上下文和输出核对。

## 当前来源和案例状态

本地盘点已经确认：破损换货只有三个共用核心模板的会话，它们属于一个开发回归组，没有独立保留集；正式商品资料和政策缺失。

本轮从已保存的 S00001 基线整理了一个结构候选，保留三个来源消息，分别对应已有图片、客服提出安排、买家接受安排。内容位于已忽略的 `.scratch/rag-prototype-20261001/damage_case_candidate.json`，不会进入公开源码示例。其 `review` 仍为 `pending`，审核人和审核时间为空，检查确认它返回 `not_reviewed`。

候选仅借鉴核实步骤，不批准“商家承担运费”或“先发后退”为通用规则。没有自动导入三段原始会话，也没有把当前候选计为已入库案例。

## 本轮验证

- 32 项合成检查通过，包含正常命中、空库、来源混淆、未审核、阶段与前提错配、未来资料与未来审核、同会话或模板、合成模式隔离、版本与有效期、旧金额和时限分离、原文指令、P0、知识版本冲突、排序稳定性、数量上限和重复标识。
- 29 个终端演示状态可以输出为 JSON。使用脚本输入验证了下一例、上一例、完整来源展示和退出流程。
- S00001 的待审核结构被排除，未作为批准样本检索。
- 现有 `test_safety.py` 的 3 项测试通过，模型调用均使用已有测试桩。
- 固定数据回归明确检查通过：10/10 不适 P0、3/3 就医 P0、37/37 风险证据追溯、8/8 黄金断言、10/10 原有合成断言、138/138 草稿状态。逐项黄金及合成结果也已检查。
- 原始 XLSX、DOCX 的 SHA256 与前次盘点一致。没有修改现有产品逻辑或桌面界面，没有调用真实模型或构建安装包。

结果位于 `.scratch/rag-prototype-20261001/`：`check-results.json`、`demo-states.json`、`terminal-smoke.txt`、`fixed-regression.json` 和 `delivery-check.json`。这些本地文件不进入 Git。当前检查不能证明独立泛化、实际回复提升或生产安全。

## 已明确的限制和下一步

处理阶段、必要前提及来源审核状态由调用方明确提供。当前没有实现自动识别阶段、审核权限管理、语义去重、任意原文净化或逐句事实核验。同模板组来自前次人工盘点；正确的分组仍是评测前提。P0 检查沿用现有规则，不增加医学判断。

下一步可围绕待审核案例要点与检索输出，设计只使用允许字段的回复上下文，并补充故意照搬旧事实的失败样例。真实模型验证仍需按数据外传与费用授权处理；在此之前可用本地假模型检验接口、失败和降级行为。

正式商品政策问答依赖可信资料，独立效果对照依赖非同模板新增样本。这两项缺口未因本轮原型通过而消失。尚不需要引入向量服务、Neo4j 或 GraphRAG。
