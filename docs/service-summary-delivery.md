# 服务摘要本地交付记录

日期：2026-09-20。版本：0.4.1。范围：Windows 桌面本地原型。

## 本轮纠正的问题

用户实际安装的程序仍显示旧“会话速览”，将首句投诉、最新处理、末句回复直接铺在右侧。本地未交付版本也仍默认使用关键词摘录，且按钮、说明和原文占据大量空间。这不满足四栏连贯概括的约定。

## 当前行为

- 正文固定为经过概述、诉求、待解决、建议；风险只留简短提醒。
- 只有两个摘要操作：生成／更新摘要、查看详情。原文引用、逐项纠正、修改历史、关联会话在详情中；订单、工单和物流合并折叠。
- 未生成时显示待生成，不把词条和原话拼接冒充语义摘要。生成和更新使用同一模型路径。
- 模型每次取得原始证据、上一版语义摘要、人工纠正（含待匹配项）；过期响应不能覆盖新资料。新资料提示更新，P0 风险单独立即更新。
- 模型输出正文最多 420 字，经过一段，其余每栏最多两项。不裁切正文；校验失败时最多请求一次校正，再失败则保留旧版。网络或 HTTP 错误不自动重试。
- 建议仍从受约束动作中选择。来源引用存在、数字来源和结构检查并不等于语义绝对正确，仍需人工核对。

## 当前两个案例

S00268 的 174 字摘要明确：消费者接受退款、凭票报销和回访；客服后续承诺不等于实际到账或回访完成。S00001 的 151 字摘要明确：已接受先发新货后退旧货、由商家承担运费并希望尽快处理。

这两个版本由本轮助手基于本地完整原文整理，带每项来源引用，作为独立版本追加到本机摘要库；没有修改原始工作簿，没有伪造用户纠正记录，也没有把它们标为真实 API 产物。其他案例不会套用这两份内容，仍需生成自己的摘要。
