# RAG 人工核对与真实模型评测方案

当前交付是可填写的核对包和评测设计。尚未执行真人评审或真实模型对照，正式政策、批准案例及独立样本仍缺失。

## 可立即使用的核对包

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/export_rag_review_packet.py --output .scratch/rag-human-review-20261001-v2
```

输出 8 份合成样例，每份包含可填写 Markdown 和完整 JSON：两个会话各覆盖固定回复、历史承诺转述、退款/时效污染和隐含到账漏检。目录存在即拒绝写入，防止覆盖人工标注；复跑使用新目录。manifest 保存初始哈希，标注前复制一份工作副本，保留原包。

JSON 保存完整消息、检索来源、规则结果、预览标识和逐句空白审核字段。所有人工结论初始为 null，状态 unreviewed；未审核不能统计为通过。样例标签和规则结果可见，因此这些包只用于熟悉审核方法，不用于盲评或模型排名。

2026-10-01 v2 更新：JSON 的 `snapshot.cutoff` 明确带时区截止点，`snapshot.case_snapshot` 保留调用方提供的完整 case（包括订单和工单）；Markdown 同时展示截止点及业务记录。空列表与未提供字段分开显示，空记录不证明业务未发生。此导出器不会替调用方核验业务记录的时间或真实性；真实数据必须先由适配层按截止点筛选并核对。当前仍只输出合成 fixture。

新版正常转述保留“预计48小时”，固定片段对寄回与运费加“若涉及”条件，自由文字样例收窄为换货进度核对。旧版目录和针对旧版的 AI 预审报告保持不变；不能把旧审核结论自动套用到新版 preview_id。新版8包全部待人工审核。

## 人工填写口径

先读截止时点内的消息与业务记录，独立列出本轮必须回应事项及其依据，再看候选。逐句检查全部正文，包括模型没有标记为 claim 的内容。

| 字段 | 需核对内容 |
| --- | --- |
| source_support | 原文是否支持该意思；填 verified_refs 和具体原话，引用存在不等于支持 |
| numbers_units | 金额用途、数字、单位、订单归属是否正确 |
| speaker_and_time | 是否把客服历史说法改成当前承诺，或引用截止点以后的信息 |
| execution_state | 是否把提出、申请、创建工单误写为退款、发货、到账、签收已完成 |
| commitment_authority | 是否新增运费承担、补偿、时效或安全保证，是否有授权来源 |
| risk_handling | 是否保留不适风险、避免诊断和治疗建议，以及无依据安全保证 |
| relevance | 是否回答当前问题，阶段是否正确，有无无关或误导内容 |

每维填写 pass / fail / uncertain / not_applicable；不适用要写理由，uncertain 不当作通过。严重程度填写 critical / major / minor / none，并给出原文和修改建议。无依据执行宣称、金额、授权承诺、安全保证或遗漏已明确的高风险处理记 critical；遗漏必要回应、错误阶段等记 major。整体填写 acceptable / revise / reject / uncertain。acceptable 仅表示该回复在本评测快照下可用，不授权发送。

response_review.required_items 必须先由原文建立，missing_items 从该清单逐条比对；避免只检查已生成的句子而漏掉未回答的问题。人工填写 reviewer、reviewed_at，争议交由另一人复核并记录 adjudicator。没有第二位评审时如实记单人审核，不声称一致性已验证。

校准关注点：历史“预计48小时”只能转述为此前说法，不能证明当前仍有效或已发货；“钱已经回到您的口袋里了”包含到账断言，即使规则未发现也须核对；SYN_B 的不适风险不得因商品破损场景而被省略。

## 真实模型对照设计（待执行）

1. 冻结消息截止点、当前订单/工单、图片缺失状态、人工必答清单、来源版本及可获得/批准时间，记录文件哈希。S00001/S00137/S00203 同模板归同一开发组；同组、当前会话和未来来源不得进入检索。现有资料不能建立独立保留集。
2. 先以空库运行 A/B 协议校验。A 为相同模型与任务提示、仅当前证据；B 仅额外增加合规检索字段，其余模型参数、输出协议、必答要求和上下文预算一致。空库或无命中只能评价降级行为，不能估计 RAG 收益。固定片段选择与自由文字生成必须分别评价。
3. 有审核通过且时间合规的异组来源后，才开展检索对照。每个快照配对运行 A/B；首轮可各重复 3 次观察波动，但重复输出不能当作独立样本。后续数量按新增独立模板组和估计精度另行确定，不从当前 3 段同模板会话推断泛化。
4. 保存模型精确标识、提示版本、参数、请求/响应、context_id、来源版本、每次延迟、返回 token 使用量、重试与错误。价格未核实时只报 token，不估算费用；失败和超时保留在分母中。日志放本地忽略目录并移除密钥。
5. 将候选随机编码给评审，隐藏 A/B、模型身份和规则判定；两侧提供相同、截止点合法的证据核对包。随机对应表单独保留。两人独立判断后复核分歧。合成v2包已可用下面的工具隐藏标签；真实模型输出适配与真人盲评尚未执行。

## 合成盲审材料（已生成，待真人审核）

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/blind_rag_review_packets.py --source .scratch/rag-human-review-20261001-v2 --output .scratch/rag-blind-review-20261001
```

工具读取已有v2合成包，先核对manifest哈希，再随机编号并按允许字段投影；不生成新回复。已经存在的输出目录会被拒绝，复跑需新目录。

- `reviewer/`：8个随机编号候选，各含Markdown和JSON；保留截止点、完整case、参考来源原文和候选正文，去掉原样例类别、预览标识、生成方式、模型声明列表及规则结论。人工栏位全部留空。
- `coordinator/mapping.json`：编号与源文件/preview_id对应关系、源哈希和评审包初始哈希。只由协调者保留，不与评审目录一起分发。

仅将reviewer目录的副本交给评审，两位评审分别填写副本；先读证据建立必答项，再核对全部正文，包括隐含的动作宣称。记录审阅人和时间，保留原包；不要将AI辅助预审填写为真人结果。核对维度及严重程度定义按本文“人工填写口径”。

导出时，同一session和cutoff的候选必须具有完全相同的核对证据，否则拒绝导出。该检查不证明来源真实或时间合规，仍依赖调用方核对。工具当前只接受v2合成校准包，不支持直接把真实模型响应作为输入。

目录分开不是访问权限隔离。看过原包的人可能识别候选，文风也可能暴露生成方式；本次结果仅证明标签隐藏和材料分发结构可运行，不表示已经完成有效盲评。真人审核、分歧复核、真实模型调用仍为0。4项针对性测试通过：字段投影、完整映射及防覆盖、源文件变更拒绝、同快照证据不一致拒绝。

## 指标与决策

| 指标 | 分母及规则 |
| --- | --- |
| 严重事实错误率 | 含至少一项 critical 的可审阅回复 / 可审阅回复；另报失败请求 / 全部请求 |
| 事实支持率 | 有证据完整支持的事实声明 / 人工识别的全部事实声明；无事实声明记不适用 |
| 必答覆盖率 | 正确回应的人工必答项 / 全部必答项；无必答项记不适用 |
| 可用回复率 | 无 critical/major、无未决项且整体 acceptable 的请求 / 全部请求；生成失败不计可用 |
| 引用支持率 | 确实支持对应声明的引用 / 全部所列引用；未引用的事实另计事实支持率 |
| 耗时与消耗 | 按每次请求保存耗时、token、失败和重试；比较配对快照，按模板组汇总 |

当前阈值是本项目待采用的验收约定，不是外部标准：开发集发现一条 critical 即先修正并复测；任一未审核或 uncertain 项不能作为通过证据。即使开发集零严重错误，也只能说明这些样例未发现错误。要声称 RAG 改善质量，必须在独立模板组上报告 A/B 配对差异、样本数、分歧、失败及不确定性，并确认改善未伴随严重错误增加。不得将同会话多时点或多次生成当作独立样本扩大统计量。

本轮没有读取密钥或调用模型 API。下一步可先由人工完成这些校准包；真实请求执行、盲评工具及独立来源补齐均需单独落地和验证。
