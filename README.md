# 共情副驾 · 美妆客服 AI 辅助工作台

将会话、订单和工单信息放到同一条处理流程中，帮助客服核对消费者诉求、查看风险依据、编辑回复，并记录需要主管跟进的问题。

本项目面向天池“数据共情者”赛题，当前交付形态是 **Windows 桌面应用与本地原型**。使用比赛提供的虚构 MOCK 数据，尚未接入真实客服渠道。

**技术栈：** Python · PySide6 · pandas / openpyxl · SQLite · 大模型 API；另保留 Streamlit 网页原型。

## 解决什么问题

客服接手一段历史对话时，需要同时判断：客户现在要解决什么、之前承诺了什么、订单或工单能证明什么，以及哪些问题应优先上报。

共情副驾把这些核对动作组织到一个工作台中。模型负责辅助整理和起草，业务事实来自只读资料，风险规则独立运行，最终回复与上报由人工操作。

## 已实现的功能

| 功能 | 用户可以完成的操作 |
| --- | --- |
| 会话检索与资料核对 | 搜索会话、阅读消息及关联订单信息，查看风险对应的来源消息 |
| 服务摘要 | 主动生成当前诉求、前期沟通、建议处理和待确认内容；查看依据并人工纠正；资料变化时提示复核 |
| 回复辅助 | 按需生成 AI 回复建议；已有草稿先预览再替换；生成失败保留原文；切换会话与重启后恢复草稿 |
| 处理清单 | 编辑待核实事项、附本机截图、选取依据并记录完成状态 |
| 客服上报与主任处理 | 勾选具体消息、填写原因并上报；主任查看原文、清单和处理状态，在本机记录处理结果 |
| 模拟对话测试 | 在独立窗口输入客户消息，测试模型回复和摘要更新；历史测试与输入草稿可恢复 |

正式工作台中的“模拟发送”只保存本地记录，不会向消费者外发消息。模拟对话窗口可自动生成测试回复，但不代表经过真实客服审核。

## 两个典型流程

### 消费者报告不适：风险提示 → 原文核对 → 人工上报

以 `S00268` 为例，确定性规则识别消费者报告的不适并显示 P0 提示。客服可以定位原始消息，核对资料与摘要，编辑谨慎的回复，再选择相关消息上报。主任工作台显示这条上报及其处理状态。

P0 是服务处理优先级，不是医学诊断；模型回复不得提供治疗建议或无依据的安全保证。

### 商品破损与换货：接手历史 → 核实诉求 → 回复与跟进

以 `S00001` 为例，客服查看已有对话和关联资料，核对当前诉求、历史沟通与尚待确认的事项，再编辑回复并维护处理清单。程序在相关数据处理中区分原订单物流与补发物流，不将已有工单等同于已发货。

两个案例均用于本地流程演示，没有执行真实退款、补偿或工单更新。

## 技术设计与代码入口

```text
只读 Excel：会话 / 订单 / 工单
              ↓
       数据关联与上下文组装
              ↓
   独立风险规则 + 按需模型辅助
              ↓
     来源核对 / 输出检查 / 状态检查
              ↓
  桌面工作台：摘要、回复、清单、上报
              ↓
       SQLite 本地记录与恢复
```

- **业务事实可追溯。** 订单号、物流号与消息 ID 按字符串读取；数据层按会话及时间组织资料，风险证据可回到原始消息。见 [数据层](copilot/data.py)、[规则与编排](copilot/agent.py)。
- **规则与模型分工。** 确定性风险提示独立于摘要和回复生成；模型不能降低规则给出的 P0。摘要处理检查结构与来源引用，失败时显示错误或提供明确的本地整理路径，不把失败输出伪装成模型结果。见 [摘要模型逻辑](copilot/summary_llm.py)、[回复模型逻辑](copilot/reply_llm.py)。
- **人工修改与异步请求协调。** 生成过程中发生编辑、会话切换或摘要变化时，避免旧建议覆盖当前内容；保留草稿及人工纠正。见 [桌面主窗口](desktop/window.py)、[接手与摘要交互](desktop/handover.py)。
- **操作与状态持久化。** 模拟回复、主动上报和处理清单分别记录；普通模拟发送不会自动创建主任上报。见 [本地存储](copilot/store.py)、[上报记录](copilot/reports.py)、[处理清单](copilot/checklist.py)。

上述检查不能保证模型语义完全正确，回复与处理建议仍需人工核对。

## 数据与产品边界

- 比赛数据包含 138 个会话、998 条消息、113 笔订单和 80 张工单，均为虚构 MOCK 数据；原始工作簿不随仓库分发。
- 资料中记录了 29 个图片路径，但本地未取得对应原图；界面须显示缺失状态，不能据此宣称已完成图像理解验证。
- 当前是本机角色演示，没有登录权限隔离、跨电脑同步或外部工单系统集成。
- 模型请求会对部分数字和邮箱进行遮蔽，这不等于完整匿名化；使用外部模型前需确认数据使用权限。
- RAG 等实验代码保留用于研究与回归，不代表已建成完整线上知识库服务。

## 本地运行

使用 Windows 与 Python 3.11。在仓库目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\.venv\Scripts\python.exe -m desktop
```

首次打开后，点击“选择 Excel”载入经授权取得的业务工作簿。**仅克隆仓库不包含业务数据，无法直接复现上述两个数据案例。** 本地记录默认保存在 `%LOCALAPPDATA%\EmpathyCopilot`，不会改写原工作簿。

在“设置 → 模型连接设置”中配置接口后，可主动生成摘要或回复；这些操作会向配置的模型服务发送上下文并可能产生费用。未配置模型时仍可读取已加载资料、查看规则提示和手工编辑回复。

独立模拟对话窗口不要求提供订单或工单资料，自动回复需要模型配置：

```powershell
.\.venv\Scripts\python.exe -m desktop.simulation
```

模拟记录单独保存在本机，不能替代有订单、工单上下文的完整案例验证。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `copilot/` | 数据读取、规则、模型辅助和本地状态 |
